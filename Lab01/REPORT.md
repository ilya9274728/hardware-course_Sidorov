Контрольные вопросы:
1.При первой сборке система создаёт выходные и промежуточные файлы. При повторной сборке она проверяет, изменились ли исходный код и настройки проекта. Если изменений нет, часть работы можно пропустить или использовать готовые результаты.

2.В bin находятся выходные файлы сборки, а в obj — промежуточные файлы и данные, используемые во время сборки. Если удалить bin, выходные файлы придётся создать заново. Если удалить obj, системе придётся заново подготовить промежуточные данные, поэтому ей может потребоваться выполнить больше работы.

3.При каждом запуске системе будет недоступна часть результатов предыдущей сборки. Она будет создавать выходные и промежуточные файлы заново, поэтому сборка может занимать больше времени.

4.В .csproj указаны настройки проекта: например, тип приложения, целевая версия .NET и другие параметры сборки. Система использует эти настройки вместе с исходным кодом, чтобы правильно собрать программу.

5.Система сборки может определить, какие файлы и результаты зависят от изменённого исходника. Она пересобирает необходимые части проекта, а остальные результаты может использовать повторно.

6.Эти каталоги содержат файлы, автоматически создаваемые при сборке. Их можно получить заново из исходного кода и настроек проекта, поэтому обычно в Git добавляют исходники и файлы проекта, а папки bin и obj исключают через .gitignore.
